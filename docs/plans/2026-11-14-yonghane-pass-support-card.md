# 용하네 수익 구조 개정안 — 광고 한 번으로 열기 + 쿠팡 응원 카드 (2026-11-14)

사용자 방향: 「결제하는 것보다 광고 하나 보는 걸 더 이득이라 생각할 텐데? 우리 장점」 · 「보상이라고 표현하지 말고 더 좋게」 · 「진행해」.
이 문서는 **설계안**이다. 용하네 저장소(`D:\FORTUNE_FUSION`)는 아직 고치지 않았다 — 이유는 §5.

## 1. 결론

- **이용권(용한패스)은 광고 한 길만.** 첫 답은 그냥 열리고, 나머지 해석은 광고 한 번으로 1시간 전부 열린다.
- **쿠팡은 열쇠에서 뺀다.** 풀이를 다 본 자리의 「용하네 응원하기」 카드로 옮긴다. 눌러도 아무것도 열리거나 쌓이지 않는다.
- 화면 · 글에서 「보상」 · 「리워드」라는 말은 쓰지 않는다 — 「열기」 · 「1시간 이용권」 · 「응원하기」.

1시간 이용권은 「플랫폼 안에서만 쓰는 양도 불가 혜택」이라 허용 범위다. 「거절해도 정상 이용을 막지 않음」은 첫 답 · 계산 값 · 근거가 늘 열려 있는 지금 설계(`yonghan-pass.ts:8-10`)로 맞춘다.

## 3. 바꿀 것 (용하네 저장소)

1. `lib/yonghan-pass.ts` — `PassSource` 에서 `'coupang'` 을 뺀다. `coupangLastAt` · `COUPANG_COOLDOWN_MS` 삭제. 저장된 옛 상태는 읽을 때 그 칸을 버린다.
2. `components/pass/PassStation.tsx` — 쿠팡 구역(53-71줄)을 지우고 `SupportCard`(새 컴포넌트)로. 문구:
   > (첫 줄) 이 링크는 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
   > 용하네는 풀이에 돈을 받지 않습니다. 쿠팡에서 평소 사시던 걸 이 링크로 들어가 사시면, 값은 그대로이고 수수료 일부가 용하네 운영비가 됩니다.
   > [용하네 응원하기]
   `SupportCard` 는 이용권 상태를 읽지도 쓰지도 않는다.
3. 자리 — 풀이가 끝난 뒤(가리지 않는 자리) + `/pass` 화면. `TASK.md:266` 이 이미 정한 「모든 풀이 끝 인라인 카드」와 같다.
4. `lib/yonghan-pass-config.ts` — `PASS_COUPANG_URL` → `SUPPORT_COUPANG_URL` 로 이름을 바꿔 뜻을 못 박는다. `PASS_AD_READY` 는 Ad Manager 보상형이 연결되고 `rewardedSlotGranted` 를 받은 뒤에만 `claim('ad')`.
5. 약속(`lib/promises.ts`) — 사용자 승인 뒤에만:
   - 6번: 「풀이에 돈을 받지 않습니다. 결제도, 코인 충전도 없습니다.」
   - 7번: 「첫 답은 그냥 열립니다. 나머지는 광고 한 번으로 1시간 동안 전부 열리고, 풀이 문장 사이에는 광고를 끼우지 않습니다. 쿠팡 링크는 풀이를 가리지 않는 자리에만 두고, 눌러도 아무것도 열리지 않습니다.」
6. 검사(`lib/free-paths.test.ts`) — 약속과 같이 고친다:
   - ④ 중간 재화: 「이용권」 낱말 면제를 파일 이름이 아니라 「광고 길만」으로 다시 정의.
   - ⑤ 「풀이 화면에 제휴 링크가 없다」 → 「제휴 링크는 `SupportCard` 한 곳에만 있고, 풀이 문장보다 뒤에 온다」.
   - 새 검사: 「쿠팡 링크를 눌러도 이용권 상태가 바뀌지 않는다」 · 「결제 · 코인 낱말이 화면 코드에 없다」(지금 ④ 유지).
7. 개인정보 · 약관 · `/pass` 안내 문구에서 「쿠팡 열면 이용권」 삭제.

## 4. 순서

1. 애드센스 승인(자체 도메인 `www.yonghane.com`) — 사용자 계정 일. 풀이 밖 공개 글 광고가 먼저 붙는다.
2. Ad Manager 계정과 웹 보상형 사용 자격 확인 — **미확인**. 안 되면 웹은 이용권 없이 전부 열어 두고(풀이 밖 광고 + 응원 카드), 이용권은 앱(AdMob 보상형)에서만.
3. §3 의 1~4 · 7(쿠팡을 열쇠에서 빼기)은 광고와 무관하게 먼저 할 수 있다 — 스위치는 꺼진 채.
4. 약속 6 · 7번 개정 + 검사 → 광고 연결 → 스위치 켜기. 켜는 커밋 하나에 약속 · 검사 · 문서가 같이 들어간다(`TASK.md:16`).

## 5. 지금 고치지 않은 이유

- 용하네 저장소는 `codex/ui-home-objects` 브랜치에 **커밋 안 된 파일 58개**가 있다(10-19~11-03 Codex 작업 — 홈 개편 · 용한패스 · 개인정보 문서 포함, `HANDOFF.md`). 그 위에 고치면 남의 작업과 섞인다. 그 묶음을 먼저 커밋하거나 정리해야 한다.
- 같은 저장소의 Cloudflare 설정 문제(`run_worker_first = true` · 캐시 `max-age=0` — 몰리면 429)도 같은 이유로 손대지 않았다.
