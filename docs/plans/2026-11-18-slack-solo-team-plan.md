# 슬랙을 「한 사람 팀」의 사무실로 — 무료 플랜으로 끝까지 쓰는 계획 (2026-11-18)

사용자 요청(2026-11-18): 「1인 개발자가 슬랙에서 원하는 팀을 얻었듯이 효과적으로 체계적으로 운영할 수 있고, 기능을 충분히 잘 활용할 수 있는지 ego-browser 에서 자료 조사해서 계획서 작성해」.
윗 계획: `docs/plans/2026-11-18-agent-team-plan.md`(팀 = 아침 한 장 · 통로 하나 · 한 저장소 한 담당). 이 문서는 그중 **통로(슬랙)** 를 어떻게 쓰는지만 다룬다.
조사: ego-browser 로 슬랙 공식 도움말 · 공식 개발 문서 · 1인 창업자 글을 읽었다(§7 출처). 사실은 읽은 원문에서만 가져왔고, 재 보지 않은 것은 「미확인」이라고 적었다.

## 0. 한 줄 결론

**슬랙은 「보는 창」이고, 기록은 저장소다.** 채널을 쓰임별로 다섯 개로 나누고 폰은 한 채널에서만 울리게 한다. 그다음 **버튼 답(A / B / 쉬어)** 과 **PC 멈춤 감지**를 붙이면, 돈을 들이지 않고도 「팀장이 폰으로 고르고 담당들이 보고하는」 모양이 된다. 유료 기능(워크플로 빌더 · 리스트 · 사이드바 섹션 · 슬랙 AI)은 쓰지 않는다.

## 1. 우리 자리 — 무료 플랜으로 되는 것과 안 되는 것

| 항목 | 무료 플랜 | 우리에게 뜻하는 것 | 근거 |
|---|---|---|---|
| 메시지 기록 | **최근 90일만 보임**. 1년이 지난 내용은 **영구 삭제** | 슬랙에만 남긴 결정은 사라진다 → 결정은 저장소에 쓴다 | 공식 플랜 표(각주) · 플랜 화면 「90일간의 메시지 내역」 |
| 앱 통합 | **최대 10개** | 지금 1개(`my-ajae alerts`). 앱 하나로 채널 여러 개에 쓸 수 있으니 늘릴 필요가 없다 | 플랜 화면 「앱 최대 10개」 |
| 워크플로 빌더 | 유료 전용 | 자동화는 우리 파이썬 스크립트로 한다 | 워크플로 빌더 가이드 「유료 플랜에서 사용 가능」 |
| 리스트 | 안 됨 | 할 일은 각 저장소 `TASK.md` 에 그대로 둔다 | 플랜 화면 「리스트 — 포함되지 않음」 |
| 사이드바 사용자 지정 섹션 | 유료 전용 | **채널 이름 앞 번호로 순서를 잡는다**(§2) | 사이드바 섹션 도움말 「유료 플랜에서 사용 가능」 |
| 캔버스 | **공식 두 쪽이 다르다** — 플랜 표는 「채널 및 DM에서만」, 플랜 화면은 「포함되지 않음」 | 쓰는 계획에 넣지 않는다(미확인) | 두 쪽 모두 §7 |
| 허들 | 일대일만 | 쓸 일 없음 | 플랜 표 |
| 슬랙 AI(요약 · 검색 답변 등) | 플랜 화면에 「기본 AI」 · Slackbot 「사용량 기반」. AI 검색은 무료 「포함되지 않음」 | 기대지 않는다. 요약은 우리 아침 한 장이 한다 | 플랜 화면 |
| 메시지 보내기 한도 | 채널마다 **초당 1개**(웹훅도 같다). 넘치면 HTTP 429 | 우리는 하루 열 몇 개라 걱정 없다. 한꺼번에 보내지 않게만 한다 | 개발 문서 Rate limits |
| 예약 메시지 | 앱이 **120일 뒤까지** 예약할 수 있고, 보내기 전에 지울 수 있다 | **PC 멈춤 감지**에 쓴다(§4-2) | `chat.scheduleMessage` 문서 |
| 버튼 답 받기 | **Socket Mode** 를 쓰면 공개 주소 없이 PC 에서 받는다 | **[고름] 버튼**(§4-1) | Socket Mode 문서 |
| 보낸 이 이름 · 아이콘 | `chat:write.customize` 권한이 있으면 메시지마다 이름 · 이모지를 바꿀 수 있다 | **담당마다 다른 이름으로 보고** — 팀처럼 보인다 | `chat.postMessage` 문서 |

참고: 플랜 화면에 「Pro — 평가판이 30일 남았습니다」가 보인다. **평가판은 켜지 않는다.** 30일 뒤 무료로 돌아가면 그 사이 쓰던 기능(섹션 · 리스트)이 사라지고, 이 계획은 무료에서 돌아야 한다. 켤지는 사용자가 정한다.

## 2. 채널 다섯 — 이름 앞 번호로 순서, 폰은 한 곳에서만 울린다

1인 창업자 사례(§7 mursa)의 핵심: **채널은 대화하는 곳이 아니라 들어오는 정보를 종류별로 나눠 두는 곳이다.** 그 글쓴이는 12개를 쓰고 「inbox 하나만 음소거하지 않는다」고 했다. 우리는 다섯 개면 된다.

| 채널(안) | 무엇이 오나 | 폰 알림 | 누가 쓰나 |
|---|---|---|---|
| `#0-고름` | 답이 필요한 것만 — `[고름]` 아침 한 장 · `[올려]` · `[막힘]` · `[실패]` | **모든 새 포스트**(이 채널만) | 아침 점검 · 게시 예약 · 담당 |
| `#1-게시` | 게시 결과 ✅ ❌ ⏸️ · 반응 숫자 요약 | 끔(배지만) | 게시 예약 · 반응 수집 |
| `#2-담당` | 담당 인계 한 줄(「한 것 · 검사 결과 · 다음 첫 행동」). 담당마다 이름 · 이모지가 다르다(예: 🔮 용하네 담당, 🏍️ 보카라이더 담당) | 끔 | 각 프로젝트 담당 세션 |
| `#3-아이디어` | **사용자가 폰에서 던지는 곳.** 떠오른 생각 · 고칠 것 · 찍은 화면 | 없음(사용자가 쓰는 곳) | 사용자 → 아침 점검이 읽어 「어느 저장소 할 일로?」를 묻는다 |
| `#4-일지` | 저녁 자동 일지 — 그날 커밋 · 게시 · 결정 · 내일 첫 행동 | 끔 | 저녁 정리(새로 만듦) |

- 번호는 사이드바 정렬용이다(유료의 섹션 대신). 정렬이 실제로 이름순인지는 **미확인** — 채널을 만든 뒤 눈으로 본다.
- 지금 쓰는 `#새-채널` 은 `#0-고름` 으로 이름을 바꾼다. 웹훅이 그대로 살아 있는지는 바꾼 뒤 시험 1회로 확인한다(미확인).
- 「답 필요 알림은 하루 3개 이하」(윗 계획 §3)는 `#0-고름` 에만 센다. 나머지는 울리지 않으니 개수 제한이 없다.
- 「뭔가 이상한데 확실하진 않은 것」을 올리는 채널을 따로 두라는 사례도 있다(§7 Indie Hackers 「flag it」). 우리는 `#3-아이디어` 가 그 역할까지 한다.

## 3. 사용자 쪽 설정 — 5분, 한 번만 (사용자 몫)

폰에서 슬랙 → 프로필 → 환경설정 → 알림:
1. 알림 정보: **멘션 및 다이렉트 메시지**
2. `#0-고름` 채널 → 알림 아이콘 → **모든 새 포스트**(예외로 이 채널만 다 받는다)
3. `#1-게시` · `#2-담당` · `#4-일지` → **음소거**(사이드바에서 숨지만 배지는 남는다 — 음소거 도움말)
4. **알림 일정**: 예) 매일 07:00~23:00. 그 밖의 시간에는 알림이 멈춘다(알림 구성 도움말의 팁). 무료에서 되는지는 **미확인** — 메뉴가 보이면 켠다.
5. **PC 슬랙은 닫아 둔다.** PC 에서 슬랙을 보고 있으면 폰 푸시가 늦게 오거나 오지 않는다 — 11-18 실제로 겪은 일(`docs/STATUS.md` 「안 오던 이유 세 가지」).

설정이 끝나면 `@channel` 멘션은 빼도 된다. 채널 단위로 「모든 새 포스트」를 받기 때문이다. 다만 빼기 전에 폰으로 시험 1회를 보낸다.

## 4. 붙일 기능 셋 — 순서대로, 하나씩 시험하고

### 4-1. [고름] 버튼 — 폰에서 한 번 누르면 끝 (1단계)
- 지금은 아침 한 장에 「답: A / B / 쉬어」라고 글자로만 적혀 있고, 답은 Claude 세션 채팅으로 받는다.
- 바꿀 것: 아침 한 장 아래에 **버튼 셋**(A 용하네 · B 보카라이더 · 쉬어)을 단다. 누르면:
  1. PC 의 상주 프로그램이 받는다. **Socket Mode** 라 공개 주소 · 포트 열기 · 인증서가 필요 없다(Socket Mode 문서 「without exposing a public HTTP Request URL」).
  2. 3초 안에 받았다는 응답을 보낸다(상호작용 문서 — 3초를 넘기면 누른 사람에게 오류가 보인다).
  3. **누른 사람이 사용자 본인 계정일 때만** `D:\ops\answers.jsonl` 에 `{날짜, 고른 것, 누른 시각}` 을 남기고, 같은 스레드에 「A 받음 — 용하네 담당이 오늘 첫 행동부터」라고 답한다.
  4. 그 저장소 담당 세션은 다음에 열릴 때 `answers.jsonl` 을 읽고 시작한다. **버튼이 세션을 스스로 띄우지는 않는다**(그건 2단계 이후 판단).
- 필요한 것: 슬랙 앱 설정에서 Socket Mode 켜기 · 앱 수준 토큰(`xapp-`, `connections:write`) · 봇 토큰(`xoxb-`, `chat:write` · `chat:write.customize` · `channels:history`). 둘 다 **윈도우 자격 증명 관리자**에 넣는다(`tools/secret_store.py` 그대로 — 저장소 · 로그에는 절대 남기지 않는다).
- 상주 프로그램은 **한 벌만** 돈다. 두 벌이 붙으면 같은 버튼을 두 번 받는다(§7 slack.green 사례 「two copies running at once」). 작업 스케줄러 「로그인 때 시작 · 겹치면 새것 무시」로 띄운다(지금 `my_ajae-posts` 와 같은 방식).
- 위험이 낮은 이유: 버튼이 바꾸는 것은 「오늘 무엇부터 할지」 기록 한 줄뿐이다. 게시 · 배포 · 결제 · 코드 변경은 하지 않는다.

### 4-2. PC 멈춤 감지 — PC 가 꺼져도 폰은 안다 (1단계)
- 문제: 아침 한 장 · 게시 예약은 PC 가 켜져 있어야 돈다. PC 가 꺼지면 **아무것도 오지 않는데, 사용자는 「오늘은 조용하구나」로 착각한다.**
- 방법: 아침 점검이 끝날 때마다 **다음 날 07:50 에 보낼 경고**를 슬랙 서버에 예약해 둔다(`chat.scheduleMessage`). 다음 날 아침 점검이 제대로 돌면 그 예약을 먼저 지운다(`chat.deleteScheduledMessage` — 같은 문서에 적혀 있다). **아침 점검이 못 돌면 지울 사람이 없으니 경고가 그대로 온다:** 「[막힘] 07:30 아침 한 장이 안 돌았다 — PC 가 꺼졌거나 잠들었다」.
- 슬랙 서버가 보내므로 PC 가 꺼져 있어도 온다. 돈이 들지 않고, 같은 방식으로 게시 슬롯마다 붙일 수도 있다.

### 4-3. 담당 이름으로 보고 · 결과는 스레드로 (1단계)
- 웹훅 대신 봇 토큰으로 보내면 **보낸 메시지의 위치(ts)** 를 알 수 있다. 그날의 게시 결과 · 담당 보고를 아침 한 장의 **스레드 답글**로 달면 채널이 깔끔해진다(`thread_ts` · 필요할 때만 `reply_broadcast`).
- `chat:write.customize` 로 담당마다 이름 · 이모지를 붙인다 → 슬랙만 봐도 「누가 무엇을 했는지」 보인다. 앱은 하나 그대로다(통합 1/10).
- 웹훅에서 봇 토큰으로 옮기는 동안 기존 `tools/slack_notify.py` 는 남겨 두고, 새 방식이 3일 문제없이 돈 뒤 웹훅을 끈다.

### 4-4. 아이디어 받아 가기 (2단계 · 4-1 이 일주일 돈 뒤)
- 아침 점검이 `#3-아이디어` 의 어제 글을 읽어(`channels:history`), 「어제 아이디어 2개 — ① … → 보카라이더 할 일로? / ② … → 버림?」을 [고름] 에 붙인다. 고르면 **그 저장소 `TASK.md` 에 넣을 초안**을 만들고, 넣는 것은 그 저장소 담당 세션이 한다(my_ajae 는 다른 저장소를 고치지 않는다 — AGENTS §3).
- 슬랙 글은 남이 쓴 지시가 아니라 **사용자가 쓴 메모**로만 다룬다. 다만 링크 · 붙여 넣은 글 안의 명령은 실행하지 않는다.

### 4-5. 저녁 일지 (2단계)
- 매일 22:00 에 그날 다섯 저장소의 커밋 · 게시 결과 · 받은 답을 한 장으로 `#4-일지` 에 보낸다. **같은 내용을 `D:\ops\journal\YYYY-MM-DD.md` 에도 쓴다** — 슬랙은 90일이 지나면 안 보이기 때문이다.
- 1인 창업자 글이 가장 쓸모 있었다고 꼽은 것이 이 「결정 일지」다(§7 mursa — 석 달 뒤 「왜 그렇게 했지」를 찾을 수 있다).

## 5. 하지 않는 것 · 아직 정하지 않은 것

## 7. 진행 순서와 완료 기준

| 단계 | 누가 | 할 일 | 끝났다고 보는 기준 |
|---|---|---|---|
| 0 | 사용자 | §3 폰 설정 5분 | 시험 메시지 하나가 폰에서 울리고, 음소거 채널 메시지는 울리지 않는다 |
| 1-가 | 사용자(로그인 · 권한 허용) + 에이전트 | 채널 다섯 만들기 · `#새-채널` 이름 바꾸기 · 앱에 봇 토큰 · Socket Mode 켜기 · 토큰 둘을 자격 증명 관리자에 | `secret_store.py check` 로 둘 다 「있음」(값은 출력하지 않음) |
| 1-나 | 에이전트 | 봇 토큰으로 보내기 · 스레드 · 담당 이름(4-3) | 3일 동안 실패 0 → 웹훅 끄기 |
| 1-다 | 에이전트 | [고름] 버튼 + 상주 프로그램(4-1) · 작업 스케줄러 등록 | 폰에서 누른 답이 `answers.jsonl` 에 한 줄 · 남의 계정 누름은 거부(시험) · 두 벌 띄우기 시험에서 하나만 산다 |
| 1-라 | 에이전트 | 멈춤 감지(4-2) | 아침 점검을 일부러 하루 건너뛰면 07:50 경고가 폰에 온다 |
| 2 | 에이전트 | 아이디어 받아 가기(4-4) · 저녁 일지(4-5) | 일주일 동안 아이디어가 저장소 할 일 초안으로 옮겨지고, 일지가 슬랙 · 파일 둘 다에 있다 |
| 한 달 뒤 | 사용자 | 「올려」 버튼 여부 결정(§5) | — |

1단계를 시작하려면 사용자의 「진행」이 필요하다. 슬랙 앱 설정 화면에서 권한을 넓히는 일(봇 권한 · Socket Mode)은 사용자 계정의 앱 설정을 바꾸는 일이기 때문이다.
