# 브리핑 — 「아재도 한다」 글 10개 윤문: 가장 쉽고 바로 이해되게

너는 세 모델 중 하나다. 다른 두 모델도 같은 브리핑을 받았다. 파일을 읽지 마라 — 재료는 아래가 전부다. 도구를 쓰지 말고 바로 답만 써라.

## 목표 (사용자 원문)
> llm 협업해서 윤문해봐 가장 쉽고 직관적으로 이해 가능하게
> (앞 대화) 아이들도 이해할만큼 가장 쉽게 설명한게 맞아?

읽는 사람: 개발을 전혀 모르는 사람. 초등학교 고학년이 읽어도 무슨 일이 있었는지 그려져야 한다.

## 절대 규칙 (어기면 그 글 전체를 버린다)
1. **사실은 바꾸지 않는다.** 글마다 붙은 「장부 facts」에 있는 사실만 쓴다. 새 사건 · 감정 · 장면 · 이유를 지어내지 마라(「밤새」 「깜짝 놀랐다」 「손이 떨렸다」 같은 것 금지).
2. **숫자는 장부 facts/title 에 글자 그대로 있는 숫자만.** 날짜 숫자 · 새 숫자 금지. 어려운 숫자를 빼는 것은 괜찮다.
3. 금지 표현: 완전 무료 · AI 사주 · 적중 · 「용하다」(효능) · 1위/최초/유일 · 확정 예언 · 공포 · 「지시 한 줄이면 앱」 「하루 만에 앱」 같은 만능론 · 「어린이용」 · 주소(도메인) · 「여러분은 어떠세요?」식 미끼 질문 · 「꿀팁 · 대박 · 역대급」.
4. 말투: 담담하게, 「~했습니다」체 유지. 자기 비하 · 억지 밈 · 젊은 척 금지. 고유명사(용하네 · 보카라이더 · 와일드 크라운 · 아는개힘 · Google Flow)는 그대로 두되, 처음 나오면 무엇인지 몇 글자로 풀어 줘도 된다.
5. 각 글 500자 이내. 첫 줄은 「무슨 일이 있었고 결과가 뭔지」가 바로 보이게(사건 + 결과).
6. 「따라 해 볼 한 가지」 줄은 남기되, 개발 용어 없이 누구나 할 수 있는 말로(예: 「AI에게 일을 시킬 때 ‘이럴 땐 하지 마’ 하나를 같이 적어 보세요.」). 의미는 원래 줄과 같게.

## 쉽게 쓰는 법
- 개발 용어는 생활 말로 바꾼다. 예: 측정 스크립트 → 방문자 수를 세는 장치 / 배포 → 새 버전을 사이트에 올리는 일 / C 드라이브 여유 0MB → 컴퓨터 저장 공간이 꽉 참 / 화면 시험 → 화면을 자동으로 점검하는 프로그램 / 모델 → AI / 색인 → 구글 검색에 잡힌 페이지 / 실기기 → 진짜 휴대폰.
- 한 문장에 한 가지. 문장은 짧게.
- 비유는 사실을 바꾸지 않는 범위에서만.

## 출력 형식 — JSON 배열 하나(코드 블록), 다른 말 최소
```json
[{"id":"P0001","text":"…","card":"카드 위 글자 30자 이내(쉽게)","hard_words_removed":["측정 스크립트","…"]}, …]
```
P0008 · P0009 는 추가로 "instagram", "x" 키에 같은 기준으로 고친 짧은 글을 넣어라(인스타는 해시태그 줄 유지).
