# 목록형 게시물 (2026-11-13 사용자 제안에서 시작)

AGENTS.md 의 절대 규칙이 이 스킬보다 위다. 특히 **장부에 없는 사건 · 숫자는 쓰지 않는다.**

## 1. 글의 모양

```
[첫 줄 훅] 읽는 사람의 고민이나 상식을 건드리는 한 문장. (예: 「쇼츠 대본, AI 하나한테만 맡기지 않습니다.」)
[구체 한 줄] 실제로 쓴 도구 이름. (예: 「Codex · Antigravity · Grok 셋을 연결해 놓고 똑같은 주문을 동시에 넣습니다.」)

[소개 한 줄] 「코딩 모르는 아재가 AI랑 만든 '<기능 이름>', 이렇게 돌아갑니다.」

① <짧은 이름>: <무엇을 하는지 — 도구 이름 · 규칙 그대로>
② …
③ …
④ …
⑤ …

[막혔던 일 한 줄] 웃기거나 아팠던 실제 사고 하나 😅 — 장부에 있는 것만.

[댓글 유도] 객관식으로. 「①대본 경쟁 / ②자막 규칙 / ④첫 장면 검사 중 번호만 찍어 주세요. 다음 글에서 그 단계만 뜯어 보여 드릴게요.」
```

- **도구 이름을 숨기지 않는다.** 「AI 셋」이 아니라 「Codex · Antigravity · Grok」, 「시험」이 아니라 「Playwright」. 읽는 사람이 무엇을 물어볼지 알게 한다(사용자 지적 2026-11-13).
- 목록 번호는 **①~⑤**. 「1단계」처럼 쓰면 검사기가 숫자로 센다(줄 첫머리 「1. 」만 예외).
- 스레드는 **500자 이하**(플랫폼 한도). 넘치면 겹치는 문장부터 뺀다 — 훅과 웃긴 줄은 살린다.
- 아침(08:20)은 「만든 단계」, 저녁(18:20)은 「막혔던 일」이 잘 맞는다. 기능 하나로 두 편이 나온다.

## 1-2. 스레드에서 실제로 먹힌 것 (2026-11-13 인기 글 446개 분석 — `docs/research/2026-11-13-threads-ai-popular.md`)

- **아침 목록형 = 퍼가기형.** 목록 · 무료 · 「저장해」 문구가 있는 글은 리포스트+공유 비율이 약 3배(확인). 끝에 「📌 저장해 두고 하나씩 따라 해 보세요」.
- **저녁 = 댓글형.** 「다들 ~?」 「여러분은?」 같은 진짜 질문이 있는 글은 댓글 비율 약 2.8배(확인). 좋아요는 보통이니 아침 글과 짝으로 쓴다.
- **첫 줄은 질문보다 숫자 걸린 결과**(「첫 주 글 18건, 실패 0건」). 첫 줄 질문은 좋아요가 약간 낮았다(경향).
- 실험 · 숫자 도전 · 돈(아낀 돈 포함) 각도가 좋아요 쪽 경향. 첫 줄 길이 · 이모지 · 도구 이름 유무는 차이 없음.
- 「댓글 남기면 자료 보내 줌」은 댓글 1위 패턴이지만 참여 조건 보상이라 쓰지 않는다(AGENTS §2-5).

## 2. 재미가 먼저다 — 고치는 건 딱 두 가지

**사용자 지시(2026-11-13): 「제발 빡빡하게 하지마. 너무 정직하고 재미없는 글은 아무도 안 본다.」**

- 훅 · 과장 · 감정 · 반말 · 이모지 · 「망합니다」 · 「현미경처럼」 · 「업로드 버튼만 누른다」 · 객관식 댓글 유도 — **다 그대로 둔다.** 검사기도 말투는 보지 않는다.
- 사용자가 다른 AI 판을 가져오면 **그 판이 기본이다.** 내 말투로 다시 쓰지 않는다. 다듬는 건 500자 맞추기 정도.
- 고치는 건 아래 두 가지뿐이고, 그것도 조용히 바꾸지 말고 **「이 문장은 이래서 걸린다 — 이렇게 바꿀까요?」 한 줄로 묻는다.** 사용자가 「그냥 가」 하면 간다.
  1. **안 일어난 일 · 지어낸 숫자** — 「AI 둘이 밤새 1,000판」(실제 9판) 같은 것. AGENTS §2-1 이 생긴 이유다.
  2. **앱이 실제로 안 하는 일을 한다고 말하는 것** — 특히 읽는 사람이 믿고 행동하는 약속(개인정보 · 결제 · 효과). 예: 「감시 프로그램이 앱 작동을 멈춘다」(시험은 만들 때 돌 뿐, 앱을 멈추지 않는다).
- 금지 표현 목록(AGENTS §2-3: 「완전 무료」 · 「AI 사주」 · 「적중」 등)은 검사기가 알아서 막는다. 그 밖의 말투는 신경 쓰지 않는다.

## 3. 절차

> 그림을 실제 코드 화면 대신 **훅 카드 네 장**(인스타툰 캐릭터 + 말풍선)으로 할 때는 6번 대신 `hook-card` 스킬.

0. **먼저 각도와 훅** — 주간 칸은 `week-plan`, 첫 두 줄은 `hook-bank`(후보 셋 · 틀 번호를 JSON `hook` 에). 올린 뒤 숫자는 `post-review`. (2026-11-14 추가 — L0002 첫 판이 「기능 설명」이라 되돌려진 뒤)

1. **기능 고르기** — 아직 글로 안 쓴 장부 사건, 또는 저장소에서 새 기능. 쓴 사건은 `posts/*/*.json` 의 `ledger` 로 확인.
2. **근거 찾기** — 해당 저장소의 README · 코드 · 시험 파일을 연다. 도구 이름, 규칙, 「막혔던 일」(코드 주석의 날짜 붙은 사고 기록이 금광이다: 예 `auto-cf/bin/script.py:96-104`).
3. **장부에 넣기** — `ledger/events.jsonl` 에 새 줄(`E0xx`). facts 는 글에 쓸 문장 그대로, 숫자 포함. source 는 `경로:줄 (HEAD 커밋)`. 근거를 못 찾은 것은 넣지 않는다.
4. **초안** — `posts/list/L0xxx.json`:
   ```json
   {"id": "L0003", "style": "목록형", "app": "maker", "ledger": ["E016", "E022"],
    "text": "…", "card": "카드 큰 글자(짧게)", "first_comment": "예시: 「…」 같은 질문 대환영입니다!",
    "image": "out/cards/list/L0003.jpg", "card_visual": "어느 파일 몇 줄을 그렸는지"}
   ```
5. **검사** — `node tools/check_post.mjs posts/list/L0003.json` 가 PASS(HOLD 는 500자 초과뿐 — 수식어 말고 중복 문장부터 뺀다).
6. **카드** — 실제 코드 줄을 그린다(지어낸 화면 금지, 생년월일 · 토큰 · 계정 값이 든 줄은 고르지 않는다):
   ```bash
   python tools/make_code_art.py <원본파일> 31,265-268 "<제목줄>" out/art/list/L0003.png
   python tools/make_card.py posts/list/L0003.json out/art/list/L0003.png out/cards/list/L0003.jpg
   ```
   다른 저장소의 main 판을 그릴 때는 `git show main:<경로> > <스크래치>/파일` 로 꺼내 그린다. 그린 카드는 Read 로 열어 눈으로 본다.
7. **사용자에게 보이기** — 본문 전문. 걸린 문장이 있으면 한 줄 질문으로만. 사용자가 「승인」해야 다음으로.
8. **승인 지문** — `posts/list/APPROVED.json` 의 items 에 `{id, app, files: {json, jpg 의 sha256}}` 추가, `approved_by` 에 사용자 말 그대로. 승인 뒤 파일을 고치면 다시 승인받는다.
9. **일정** — `posts/list/SCHEDULE.json` 의 slots 에 `{"date", "time": "08:20" | "18:20", "id"}`. 이미 지난 시각은 다음 칸으로.
10. **게시 직전 확인** — 슬롯마다 `python -X utf8 tools/run_schedule.py --show <id>` 전문을 사용자에게 그대로 보여 주고 「올려」를 받으면 `--confirm <id> --date <날짜> --by "<사용자 말>"`. 대기 프로세스는 확인 없는 슬롯을 2시간 앞두고 전문을 출력하고 코드 3 으로 끝난다 — 그 출력을 보여 주고, 확인받은 뒤 다시 건다. 확인이 없으면 올리지 않는다(사용자 지시 2026-11-13).
    **게시** — 먼저 `--dry`, 그다음 백그라운드로:
    ```bash
    python tools/run_schedule.py --sched posts/list/SCHEDULE.json --wait --dry
    python -u tools/run_schedule.py --sched posts/list/SCHEDULE.json --wait     # run_in_background
    ```
    이 프로세스가 살아 있고 컴퓨터가 깨어 있어야 한다(`request_keep_awake`). 윈도우 작업 스케줄러 등록은 자동 모드에서 거부되므로 사용자 몫(`tools/register_schedule.ps1` 을 본떠).
    본글 → `first_comment` 순으로 스레드 · 인스타에 올리고 `posts/published.jsonl` 에 남는다. 인스타 댓글은 권한(instagram_business_manage_comments)이 없으면 실패로 기록만 된다.
11. **기록** — `docs/STATUS.md` 에 한 줄, 커밋.
