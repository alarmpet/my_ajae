# 훅 카드 (2026-11-15)

AGENTS.md 의 절대 규칙이 위다. 카드의 글자도 본문과 같다 — **장부에 없는 사건 · 숫자, 앱이 안 하는 일, 「광고 없음」은 쓰지 않는다.**

## 0. 왜 이 모양인가 (근거 `docs/research/2026-11-15-hook-cards.md`)

- 사주 광고 그림 72장(메타 광고 라이브러리)은 거의 전부 **사람 얼굴이 나오는 손그림 만화 + 말풍선 + 한 줄 사연 + 밝은 바탕 + 여러 장**이었다.
- 스레드 인기 글 670개에서 그림 네 장 이상이 한 장보다 반응이 좋았다(좋아요 중앙 84.5 대 44.5 · 퍼가기 35.5 대 9). 인과는 아니다.
- 1판(어두운 바탕 + 도형 + 한 장)은 사용자가 「너무 약해」로 반려했다. 사람 · 표정 · 사연이 없었다.

## 1. 만화체인가 실사인가

**기본은 만화체(인스타툰)다. 실사풍 AI 인물은 쓰지 않는다.**

| | 만화체 | 실사풍 AI 인물 | 실제 화면 캡처 |
|---|---|---|---|
| 같은 분야 광고가 쓰는가 | 72장 대부분 | 본 것 중 한두 곳(오래된 사진풍) | 만화 칸 안에 증거로 넣는다 |
| 표정 · 감정 | 과장해도 자연스럽다 | 어색하면 바로 티가 난다 | 없음 |
| 「가짜 사람」 위험 | 없다 — 누가 봐도 그림 | 있다 — 실제 이용자 사진처럼 읽히면 가짜 후기가 된다(AGENTS §2-5) | 없다 |
| AI 표시 | 의무 대상 아님 | 사실적 생성물 — 표시해야 한다(AGENTS §2-8) | 해당 없음 |
| 같은 인물 이어 가기 | 묘사를 그대로 쓰면 이어진다(실측 6/6) | 얼굴이 장마다 달라진다 | — |

- **훅(첫 장) = 만화체.** 불만 · 감정을 보여 주는 자리다.
- **증거(셋째 장) = 실제 화면 캡처.** 「용하네는 이렇게」를 보여 줄 때는 운영 사이트를 폰 폭으로 찍은 진짜 화면이 가장 세다(`posts/list/IDEAS-yonghane.md` 캡처 요령). 실사가 필요한 자리는 여기다 — AI 로 만든 실사가 아니라 진짜 화면.
- 우리 계정에서 어느 쪽이 더 먹히는지는 **재 보지 않았다.** 올린 뒤 `post-review` 로 카드 종류(만화 훅 / 화면 캡처 / 영상)를 견준다. 표본이 5개 미만이면 결론을 내지 않는다.

## 2. 네 장의 구조

| 장 | 무엇 | 글자 |
|---|---|---|
| ① 훅 | 꼬리표 한 줄 + 큰 글자 두 줄(마지막 줄에 형광펜) + 캐릭터(표정) + 말풍선 | `tag` · `hook` · `bubble` |
| ② 공감 | 리뷰 · 실제 사건에서 본 불만의 모양 두세 가지 | `pain_title` · `pain` |
| ③ 답 | 용하네(또는 그 앱)가 한 선택 세 가지 + **약점 한 줄** | `answer_title` · `answer` · `answer_note` |
| ④ 질문 | 댓글로 한마디에 답할 수 있는 물음 + 같은 캐릭터 | `ask` · `ask_bubble` |

훅 쓰는 법:
- **낱말이 아니라 일어난 일.** 「광고 불만」이 아니라 「닫기 눌렀는데 광고가 또 열림」. 끝을 「~함 · ~림」으로 끊으면 사연처럼 읽힌다.
- 말풍선은 읽는 사람이 속으로 하는 말(「아니 닫기 눌렀다고…」). 두 줄, 줄마다 9자 안쪽.
- 첫 장에 앱 이름 · 기능 · 자랑을 넣지 않는다. 카드는 멈추게 하고, 앱 이야기는 ③ 장과 본문이 한다.
- **지어낸 사연 금지.** 「~했더니 결혼함」 같은 남의 광고 문법은 가져오지 않는다. 훅은 장부에 있는 불만 · 사건만(리뷰 조사 E041 같은 것).

## 3. 절차

1. **본문이 먼저.** `hook-bank` → `list-post` 로 글을 쓰고 검사를 통과시킨다.
   - **그림을 만들기 전에 본문과 카드 글자 전문을 사용자에게 보이고 OK 를 받는다**(사용자 지시 2026-11-19 「앞으로 이미지 만들기 전에 나한테 먼저 글을 보여줘」). 근거: L0036 「자명종 맞춰 놨는데 앱이 3주 내내 잠」을 확인 없이 그림까지 만들었다가 「도대체 뭔 내용이야?」로 반려 — 비유가 안 통하는 글은 그림이 살리지 못한다.
2. **게시물 JSON 에 `cards` 를 넣는다**(글자는 여기서만 정한다 — 도구는 짓지 않는다):
   ```json
   "cards": {"color": "pink", "tag": "사주 앱 쓰다가", "hook": ["닫기 눌렀는데", "광고가 또 열림"], "bubble": "아니\n닫기 눌렀다고…",
     "pain_title": "리뷰 2,790개에서 본\n광고 불만의 모양", "pain": ["닫기가 안 된다", "결과 보기 직전에\n끼어든다"],
     "answer_title": "그래서 용하네는", "answer": ["…", "…", "…"], "answer_note": "대신 …는 없습니다",
     "ask": ["광고, 어디까지면", "참을 만하세요?"], "ask_bubble": "A · B · C\n골라 주세요"}
   ```
   `color` 는 pink · sky · lilac · yellow · mint · peach. 한 주 안에서 겹치지 않게.
3. **캐릭터 그림을 Flow 로 만든다**(§4). 받은 그림을 `out/art/hook/<글 번호>.jpg` 로 둔다. 그림이 없으면 도구가 낙서 캐릭터로 대신 그린다(약하다).
4. **카드 만들기:** `python -X utf8 tools/make_hook_cards.py L0027 L0028` → `out/cards/list/<id>-1~4.jpg`.
5. 게시물 JSON 에 `"carousel": ["out/cards/list/<id>-1.jpg", … "-4.jpg"]` 와 `"image"`(첫 장), `"card_visual"`(무엇으로 그렸는지 — Flow 생성 그림이라고 적는다).
6. **눈으로 본다.** 네 장을 한 줄로 붙여 Read 로 연다. 확인할 것: 큰 글자가 머리를 가리지 않는가 · 말풍선이 얼굴을 가리지 않는가 · 아래 띠가 Flow 표시(✦)를 덮었는가 · 글자가 칸을 넘치지 않는가.
7. 승인 → 지문 → 슬롯 → 게시 직전 확인은 `list-post` §3-7 이후 그대로. **카드를 다시 만들면 파일이 바뀌어 승인이 무효가 된다** — 승인받은 뒤에는 도구를 다시 돌리지 않는다.

## 4. Flow 로 캐릭터 그리기 (ego-browser)

사용자 지시(2026-11-15): **「한 장씩 시간 텀 1~2분 정도씩 주고 생성해」.** 화면 구조 · 함정의 정본은 사용자 스킬 `flow-browser-ops` 다 — 처음이면 그것부터 읽는다.

1. `C:/Users/petbl/ego/flow-hook-<날짜시각>/` 를 만들고 `scripts/flow-images.mjs` 와 `scripts/jobs.example.json`(→ `jobs.json`)을 복사한다.
2. `flow-images.mjs` 의 `D` 를 그 폴더로 바꾼다. `jobs.json` 의 `jobs` 에 `[파일 이름, 장면 한 문장]` 을 넣는다. 파일 이름을 글 번호(`L0027`)로 하면 3번 단계에서 이름을 안 바꿔도 된다.
3. `node --check flow-images.mjs` — 문법 오류가 있으면 ego-browser 는 오류 없이 영원히 멈춘다.
4. 백그라운드로 실행한다(여섯 장에 약 13분 — 포그라운드 10분 한도를 넘는다):
   `ego-browser nodejs -e 'await import("file:///C:/Users/petbl/ego/<폴더>/flow-images.mjs")'`
5. `out/log.txt` 를 본다. 첫 장이 「받음」으로 찍히면 그 그림을 Read 로 열어 화풍을 확인하고, 이상하면 멈추고 프롬프트를 고친다(나머지는 건너뛰지 않으니 파일을 지우고 다시 건다).
6. 끝 줄이 「끝」이면 `out/*.jpg` 를 `D:/my_ajae/out/art/hook/` 로 복사한다.

스크립트가 지키는 것(고치지 말 것):
- **이미지 모드 · 비율 · x1 · 「생성 시 0 크레딧」을 확인한 뒤에만 제출**한다. 새 프로젝트는 동영상 모드로 열린 적이 있다(2026-11-15) — 동영상은 크레딧이 든다.
- 한 장씩: 제출 → 진행률이 사라지고 받기 단추가 늘어남 → 받기 → 90초 쉼. 실측 6장 실패 0, 한 장 약 30초.
- 제출 확인이 안 되면 다시 누르지 않는다. 「비정상적인 활동」이 보이면 멈춘다.
- 이미 받은 파일은 건너뛴다 — 끊기면 같은 명령으로 잇는다.

프롬프트 틀(`jobs.example.json` 의 `base` · `end`):
- **같은 인물 묘사를 글자 그대로 되풀이**한다(검은 단발 · 크림색 카디건 · 흰 티). 여섯 장에서 같은 캐릭터로 이어졌다.
- 장면은 **표정 + 손이 하는 일 + 소품 하나 + 바탕색** 한 문장. 표정 낱말: angry annoyed / shocked wide eyes / confused dizzy swirly eyes / tired half-closed eyes / eyes shut covering ears / gloomy pouting.
- 「placed on the right half」 + 「left third is plain empty background」 — 왼쪽에 말풍선 자리가 생긴다.
- 「Text-free image, speech-bubble-free image.」 — 글자 · 말풍선은 도구가 얹는다(AI 그림의 한글은 틀린다).
- 다른 캐릭터(아재 본인 · 남자 · 중년)를 쓰려면 `base` 의 인물 묘사만 바꾸고, 그 묘사를 그 글 묶음 내내 유지한다.

## 5. 하지 않는 것

- 실사풍 AI 인물을 이용자 · 후기처럼 쓰기(가짜 후기).
- 남의 광고 그림 · 캐릭터를 참조 이미지로 넣기. 남의 그림을 저장소에 싣기.
- 로그인 안내 창 · 가림막을 걷어 내고 남의 글 그림을 캡처하기(2026-11-15 스레드에서 막혔다 — 접근 제한 우회다). 공개된 곳(메타 광고 라이브러리)만 본다.
- Flow 에서 연달아 빠르게 제출하기 · 막혔다고 다른 계정으로 옮기기.
- 다른 앱 저장소의 화면을 지어내기 — ③ 장에 화면을 넣을 때는 운영 사이트의 실제 캡처만.

## 6. 손댈 때 알아 둘 것

- `tools/make_hook_cards.py` 를 셸에서 고칠 때 **`\n` 이 든 문자열을 sed · heredoc 으로 바꾸지 않는다** — 실제 줄바꿈으로 풀려 문법 오류가 났고 sed 로는 안 고쳐졌다(2026-11-15). Edit 도구로 고친다.
- 글꼴은 `C:/Windows/Fonts/NotoSansKR-VF.ttf`(가변 글꼴 · `set_variation_by_name('Black')`). 손글씨 글꼴은 이 PC 에 없다.
- 그림 찾는 순서: `cards.art` → `out/art/hook/<글 번호>.jpg` → 도구 안의 ART 표(L0021~L0026).
- `out/` 은 gitignore 다 — 그림 · 카드는 이 PC 에만 있다.
